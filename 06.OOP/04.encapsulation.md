### 🔒 کپسوله‌سازی یعنی چی؟

توی دنیای واقعی، خیلی از چیزها رو نمی‌ذاریم هر کسی هر جوری دستکاری کنه. مثلاً تلویزیون رو شما با دکمه‌های کنترل کنترل می‌کنی، نه اینکه مستقیم بری توی مدارهای الکترونیکیش دست ببری!

کپسوله‌سازی در برنامه‌نویسی دقیقاً همین مفهومه: **جزئیات داخلی یک شیء رو پنهان می‌کنیم و فقط راه‌های امن برای دسترسی به اون‌ها فراهم می‌کنیم.**

> **📌 چهار اصل اصلی شی‌گرایی (OOP):**
> 1. **ارث‌بری (Inheritance)** ✅ (درس قبل)
> 2. **کپسوله‌سازی (Encapsulation)** 📍 (این درس)
> 3. **چندریختی (Polymorphism)** ➕ (درس بعد)
> 4. **انتزاع (Abstraction)**

---

### 🔑 سطوح دسترسی در پایتون

پایتون سه سطح دسترسی برای ویژگی‌ها و متدها داره:

| سطح | علامت | معنی | دسترسی |
|-----|-------|------|---------|
| **عمومی (Public)** | بدون علامت | قابل دسترسی از همه‌جا | `self.name` |
| **محافظت‌شده (Protected)** | `_` (یک خط زیرین) | فقط داخل کلاس و فرزندان | `self._name` |
| **خصوصی (Private)** | `__` (دو خط زیرین) | فقط داخل خود کلاس | `self.__name` |

### 💻 کپسوله‌سازی در عمل

#### ۱. ویژگی‌های عمومی (Public)

```python
class Person:
    def __init__(self, name, age):
        self.name = name      # عمومی
        self.age = age        # عمومی

# دسترسی مستقیم
p = Person("احمد", 25)
print(p.name)   # خروجی: احمد
p.age = 30      # تغییر مستقیم
print(p.age)    # خروجی: 30
```

#### ۲. ویژگی‌های محافظت‌شده (Protected) - با `_`

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age      # محافظت‌شده
    
    def get_age(self):
        return self._age

# هنوز قابل دسترسی‌ست ولی به عنوان یک هشدار
p = Person("احمد", 25)
print(p._age)  # کار می‌کنه ولی نشون میده نباید مستقیم دسترسی داشته باشی
```

> **💡 نکته:** `_` یه قرارداد هست، نه قانون سخت‌گیرانه. یعنی به برنامه‌نویس می‌گیم «این رو مستقیم دست نزن».

#### ۳. ویژگی‌های خصوصی (Private) - با `__`

```python
class BankAccount:
    def __init__(self, account_number, balance):
        self.account_number = account_number
        self.__balance = balance  # خصوصی - قابل دسترسی نیست
    
    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"✅ {amount:,} تومان واریز شد.")
        else:
            print("❌ مبلغ واریزی باید مثبت باشد.")
    
    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            print(f"✅ {amount:,} تومان برداشت شد.")
        else:
            print("❌ موجودی کافی نیست یا مبلغ نامعتبر است.")
    
    def show_balance(self):
        print(f"💰 موجودی: {self.__balance:,} تومان")

# استفاده
account = BankAccount("1234", 1000000)

# ❌ خطا! دسترسی به ویژگی خصوصی
# print(account.__balance)  # AttributeError!

# ✅ راه درست: استفاده از متدهای عمومی
account.deposit(500000)      # ✅ 500,000 تومان واریز شد.
account.withdraw(200000)     # ✅ 200,000 تومان برداشت شد.
account.show_balance()       # 💰 موجودی: 1,300,000 تومان
```

### 🛠️ Getter و Setter (دسترسی کنترل‌شده)

گاهی می‌خوایم وقتی یه ویژگی رو می‌خونیم یا تغییر می‌دیم، یه اعتبارسنجی انجام بدیم. اینجا از Getter و Setter استفاده می‌کنیم:

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.__age = age
    
    # Getter: دریافت سن با اعتبارسنجی
    def get_age(self):
        return self.__age
    
    # Setter: تنظیم سن با اعتبارسنجی
    def set_age(self, new_age):
        if new_age < 0:
            print("❌ سن نمی‌تواند منفی باشد!")
        elif new_age > 150:
            print("❌ سن معتبر نیست!")
        else:
            self.__age = new_age
            print(f"✅ سن به {new_age} به‌روزرسانی شد.")
    
    def introduce(self):
        print(f"👤 نام: {self.name}، سن: {self.__age}")

# استفاده
user = User("سارا", 25)
user.introduce()        # 👤 نام: سارا، سن: 25

user.set_age(-5)        # ❌ سن نمی‌تواند منفی باشد!
user.set_age(30)        # ✅ سن به 30 به‌روزرسانی شد.
user.set_age(200)       # ❌ سن معتبر نیست!

print(user.get_age())   # 30
```

### 🎯 مزایای کپسوله‌سازی

| مزیت | توضیح |
|-------|-------|
| **امنیت** | جلوگیری از تغییرات نادرست و غیرمجاز |
| **کنترل** | اعتبارسنجی ورودی‌ها قبل از تغییر |
| **پنهان‌سازی** | کاربر نیازی به دانستن جزئیات داخلی نداره |
| **انعطاف‌پذیری** | می‌تونی پیاده‌سازی داخلی رو عوض کنی بدون تأثیر روی بقیه کد |

### 📌 اشتباهات رایج در این درس

> **🔴 فکر کردن اینکه `__` کاملاً غیرقابل دسترسه:**
```python
class Test:
    def __init__(self):
        self.__secret = 10

t = Test()
# هنوزم میشه بهش دسترسی پیدا کرد! (با اسم تغییر یافته)
print(t._Test__secret)  # 10 (این روش رو نباید استفاده کنی!)
```

> **🟡 استفاده از `_` برای همه چیز:**
```python
class Car:
    def __init__(self):
        self._brand = "Toyota"  # استفاده بی‌دلیل از _

# فقط برای چیزایی که واقعاً محافظت می‌خوان استفاده کن
```

> **🟢 فراموش کردن اعتبارسنجی در Setter:**
```python
def set_age(self, age):
    self.__age = age  # ❌ هیچ اعتبارسنجی‌ای انجام نشد
```

### 🛠️ نوبت توئه: چالش مدیریت سن کاربر با کپسوله‌سازی!

بیا یک کلاس بسازیم که از کپسوله‌سازی برای محافظت از اطلاعات کاربر استفاده کنه.

**صورت مسئله:**

1. کلاس `Person` با این ویژگی‌ها بساز:
   - `name` (عمومی)
   - `__age` (خصوصی)

2. متدهای زیر رو اضافه کن:
   - `get_age()`: سن رو برگردونه
   - `set_age(new_age)`: سن رو با اعتبارسنجی تغییر بده (فقط اعداد بین ۰ تا ۱۲۰ قبول بشن)
   - `introduce()`: اطلاعات کامل رو چاپ کنه

3. بیرون از کلاس، یک شیء بساز و این کارها رو انجام بده:
   - معرفی کاربر
   - تلاش برای تنظیم سن با مقدار نامعتبر (مثلاً ۱۵۰)
   - تنظیم سن با مقدار معتبر (مثلاً ۳۰)
   - معرفی مجدد کاربر

### 💪 چالش دوم (اختیاری - برای توسعه‌دهندگان سیستم‌های امن!)

حالا که با کپسوله‌سازی آشنا شدی، یه کلاس **مدیریت اطلاعات کارت اعتباری** بساز با امنیت بالا:

1. کلاس `CreditCard` با این ویژگی‌های خصوصی:
   - `__card_number` (شماره کارت - ۱۶ رقمی)
   - `__pin` (رمز - ۴ رقمی)
   - `__balance` (موجودی)
   - `__is_blocked` (وضعیت مسدودی)

2. این متدها رو اضافه کن (همه با اعتبارسنجی):
   - `verify_pin(pin)`: رمز رو بررسی کنه و دسترسی بده
   - `show_balance(pin)`: فقط با رمز درست موجودی رو نشون بده
   - `withdraw(pin, amount)`: با رمز درست و موجودی کافی برداشت کنه
   - `deposit(amount)`: واریز به حساب (بدون نیاز به رمز)
   - `change_pin(old_pin, new_pin)`: تغییر رمز با تأیید رمز قدیمی
   - `block_card(pin)`: مسدود کردن کارت با رمز

3. برای تمام متدها اعتبارسنجی انجام بده:
   - شماره کارت باید ۱۶ رقم باشه
   - رمز باید ۴ رقم باشه
   - مبلغ برداشت نباید از موجودی بیشتر باشه
   - کارت مسدود شده نباید قابل استفاده باشه
