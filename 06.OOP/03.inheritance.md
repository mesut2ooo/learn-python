# 🎥 فصل ششم: شی‌گرایی (OOP)

## 🎯 درس ۶.۳: ارث‌بری (Inheritance)

---

### 🧬 ارث‌بری یعنی چی؟

فرض کن می‌خوایم کلاس‌های مختلفی بسازیم که خیلی از رفتارهایشان شبیه به هم است. مثلاً کلاس «پرنده»، کلاس «پستاندار» و کلاس «خزنده». همه‌ی این‌ها در نهایت «جانور» هستند و ویژگی‌های مشترکی مثل «نفس کشیدن» یا «غذا خوردن» دارند. آیا باید برای تک‌تک آن‌ها این کدهای مشترک را از نو بنویسیم؟

اصلاً! اینجاست که جذاب‌ترین ویژگی شی‌گرایی یعنی **ارث‌بری (Inheritance)** وارد بازی میشه.

> **📌 تعریف رسمی:**
> ارث‌بری یعنی یک کلاس جدید (کلاس فرزند یا **Child Class**) می‌تونه تمام ویژگی‌ها و متدهای یک کلاس قدیمی‌تر (کلاس پدر یا **Parent Class**) رو به ارث ببره، بدون اینکه نیاز باشه دوباره کدهای اون رو بنویسه. علاوه بر این، فرزند می‌تونه ویژگی‌ها و رفتارهای منحصر‌به‌فرد خودش رو هم داشته باشه.

---

### 💻 شبیه‌سازی با کد پایتون

#### ساختار کلی ارث‌بری

```python
# کلاس پدر (پایه)
class ParentClass:
    def __init__(self, attribute):
        self.attribute = attribute
    
    def parent_method(self):
        print("این متد از کلاس پدر است.")

# کلاس فرزند (مشتق شده) - کلاس پدر را داخل پرانتز جلویش می‌نویسیم
class ChildClass(ParentClass):
    # این کلاس تمام ویژگی‌ها و متدهای ParentClass را ارث می‌برد
    
    def child_method(self):
        print("این متد مخصوص کلاس فرزند است.")
```

---

### 🚗 مثال عملی: وسایل نقلیه

بیا یک کلاس پدر به نام `Vehicle` (وسیله نقلیه) بسازیم و بعد کلاس `Motorcycle` (موتورسیکلت) و `Car` (ماشین) رو به عنوان فرزندش تعریف کنیم:

```python
# کلاس پدر (پایه)
class Vehicle:
    def __init__(self, brand, color):
        self.brand = brand
        self.color = color
    
    def start_engine(self):
        print(f"🚗 موتور وسیله نقلیه {self.brand} {self.color} روشن شد. 🔑")
    
    def stop_engine(self):
        print(f"🚗 موتور وسیله نقلیه {self.brand} خاموش شد. 🔒")

# کلاس فرزند ۱: موتورسیکلت
class Motorcycle(Vehicle):
    # متد اختصاصی برای کلاس فرزند
    def wheelie(self):
        print(f"🏍️ موتورسیکلت {self.brand} تک‌چرخ زد! ⚡")
    
    # بازنویسی متد پدر (Override)
    def start_engine(self):
        print(f"🏍️ موتور موتورسیکلت {self.brand} با صدای بلند روشن شد! برووم برووم! 🔥")

# کلاس فرزند ۲: ماشین
class Car(Vehicle):
    def __init__(self, brand, color, doors):
        # فراخوانی سازنده پدر با super()
        super().__init__(brand, color)
        self.doors = doors  # ویژگی جدید
    
    def honk(self):
        print(f"🚗 ماشین {self.brand} بوق زد: بِییییپ! 📢")
```

---

### 🔑 استفاده از `super()`

وقتی می‌خوایم در کلاس فرزند، متد سازنده (`__init__`) رو بازنویسی کنیم ولی همچنان ویژگی‌های پدر رو هم داشته باشیم، از `super()` استفاده می‌کنیم:

```python
class Car(Vehicle):
    def __init__(self, brand, color, doors):
        # این خط سازنده‌ی پدر رو صدا می‌زنه و brand و color رو تنظیم می‌کنه
        super().__init__(brand, color)
        self.doors = doors  # ویژگی جدید مخصوص کلاس Car
```

> **💡 نکته:** `super()` یعنی «نسخه‌ی پدر رو صدا بزن». به کمک اون می‌تونی به متدهای کلاس پدر دسترسی داشته باشی.

---

### 🎯 بازنویسی متدها (Method Overriding)

فرزند می‌تونه یک متد از پدر رو با کد جدید بازنویسی کنه:

```python
class Motorcycle(Vehicle):
    def start_engine(self):  # بازنویسی متد start_engine از پدر
        print(f"🏍️ موتور موتورسیکلت {self.brand} با صدای بلند روشن شد! برووم برووم! 🔥")
```

وقتی این متد رو صدا بزنی، نسخه‌ی بازنویسی‌شده اجرا میشه، نه نسخه‌ی پدر.

---

### 🔍 نحوه‌ی استفاده

```python
# ساخت اشیاء از کلاس‌های فرزند
my_bike = Motorcycle("Honda", "قرمز")
my_car = Car("Toyota", "نقره‌ای", 4)

# متدهای ارث‌برده از پدر
my_bike.stop_engine()  # خروجی: 🚗 موتور وسیله نقلیه Honda قرمز خاموش شد. 🔒

# متد بازنویسی‌شده
my_bike.start_engine()  # خروجی: 🏍️ موتور موتورسیکلت Honda با صدای بلند روشن شد! برووم برووم! 🔥

# متد اختصاصی فرزند
my_bike.wheelie()  # خروجی: 🏍️ موتورسیکلت Honda تک‌چرخ زد! ⚡

# متدهای ماشین
my_car.start_engine()  # خروجی: 🚗 موتور وسیله نقلیه Toyota نقره‌ای روشن شد. 🔑
my_car.honk()          # خروجی: 🚗 ماشین Toyota بوق زد: بِییییپ! 📢
print(my_car.doors)    # خروجی: 4
```

### 📊 سلسله‌مراتب ارث‌بری

```python
class Animal:          # کلاس پدر
    def breathe(self):
        print("نفس می‌کشد")

class Mammal(Animal):  # فرزند Animal
    def feed_milk(self):
        print("شیر می‌دهد")

class Dog(Mammal):     # فرزند Mammal (نوه‌ی Animal)
    def bark(self):
        print("هاپ هاپ!")
```

همه‌ی این‌ها کار می‌کنن:
```python
dog = Dog()
dog.breathe()   # از Animal ارث برده
dog.feed_milk() # از Mammal ارث برده
dog.bark()      # مخصوص خودش
```

### 🆚 انواع ارث‌بری

| نوع | توضیح | مثال |
|-----|-------|------|
| **تک‌ارث‌بری** | یک فرزند از یک پدر ارث می‌بره | `class A(B):` |
| **چندسطحی** | زنجیره‌ای از ارث‌بری | `A -> B -> C` |
| **چندارث‌بری** | یک فرزند از چند پدر ارث می‌بره | `class A(B, C):` |

> **⚠️ نکته:** پایتون از چندارث‌بری پشتیبانی می‌کنه، ولی استفاده ازش رو با احتیاط انجام بده چون می‌تونه پیچیده بشه.

### 📌 اشتباهات رایج در این درس

> **🔴 فراموش کردن پرانتز و کلاس پدر موقع تعریف فرزند:**
```python
class Developer Employee:  # ❌ اشتباه! کلاس پدر باید داخل پرانتز باشه
class Developer(Employee):  # ✅ درسته
```

> **🟡 فراموش کردن `super().__init__()` در سازنده‌ی فرزند:**
```python
class Developer(Employee):
    def __init__(self, name, language):
        # ❌ فراموش شده! ویژگی‌های پدر مقداردهی نمیشن
        self.language = language

class Developer(Employee):
    def __init__(self, name, language):
        super().__init__(name)  # ✅ درسته
        self.language = language
```

> **🟢 اشتباه در نام `super()`:**
```python
class Developer(Employee):
    def __init__(self, name):
        super().__init__(name)  # ✅ درسته
        super()  # ❌ super() باید همراه با نقطه و متد استفاده بشه
```

> **🟣 فکر کردن اینکه فرزند نمی‌تونه متد پدر رو تغییر بده:**
```python
class Animal:
    def sound(self):
        print("صدای حیوان")

class Dog(Animal):
    def sound(self):  # ✅ میشه متد پدر رو بازنویسی کرد
        print("هاپ هاپ!")
```

### 🛠️ نوبت توئه: چالش سیستم پرسنلی کارمندان!

بیا یک سیستم ساده برای مدیریت پرسنل یک شرکت بنویسیم که از ارث‌بری استفاده می‌کنه.

**صورت مسئله:**

1. کلاس پدری به نام `Employee` (کارمند) بساز که در متد سازنده‌اش (`__init__`) یک ویژگی به نام `name` دریافت کند.
2. کلاس فرزندی به نام `Developer` (برنامه‌نویس) بساز که از کلاس `Employee` ارث‌بری کند.
3. داخل کلاس فرزند (`Developer`)، یک متد اختصاصی به نام `write_code` بنویس که چاپ کند:
   `"کارمند [Name] در حال کدنویسی با پایتون است... 💻"`
   *(به جای `[Name]` باید نام برنامه‌نویس با استفاده از `self.name` قرار بگیره).*
4. بیرون از کلاس، یک شیء از کلاس فرزند به نام `dev1` بساز و نام خودت رو به سازنده‌اش پاس بده.
5. متد `write_code` را برای شیء `dev1` صدا بزن تا خروجی رو ببینی.

### 💪 چالش دوم (اختیاری - برای معماران سیستم!)

حالا که با ارث‌بری آشنا شدی، یه سیستم **مدیریت اشکال هندسی** کامل بساز:

1. کلاس پدر `Shape` (شکل) بساز با:
   - ویژگی `color` (رنگ)
   - متد `area()` که فعلاً `0` برگردونه (چون شکل عمومی هست)

2. کلاس `Rectangle` (مستطیل) بساز که از `Shape` ارث می‌بره:
   - ویژگی‌های `width` و `height`
   - بازنویسی `area()` برای محاسبه مساحت مستطیل (`width * height`)
   - متد `perimeter()` برای محاسبه محیط مستطیل (`2 * (width + height)`)

3. کلاس `Circle` (دایره) بساز که از `Shape` ارث می‌بره:
   - ویژگی `radius`
   - بازنویسی `area()` برای محاسبه مساحت دایره (`3.14 * radius ** 2`)
   - متد `circumference()` برای محاسبه محیط دایره (`2 * 3.14 * radius`)

4. کلاس `Square` (مربع) بساز که از `Rectangle` ارث می‌بره:
   - فقط `width` می‌گیره و `height` رو برابر `width` قرار میده
   - نیازی به بازنویسی `area()` و `perimeter()` نداره (از مستطیل ارث برده)

5. از هر کلاس یک شیء بساز و مساحت و محیط رو چاپ کن.

**نمونه خروجی:**
```text
مستطیل قرمز: مساحت = 50، محیط = 30
دایره آبی: مساحت = 78.5، محیط = 31.4
مربع سبز: مساحت = 25، محیط = 20
```

> **💡 نکته:** برای مساحت دایره از `math.pi` هم می‌تونی استفاده کنی ولی برای سادگی از `3.14` استفاده کن.
